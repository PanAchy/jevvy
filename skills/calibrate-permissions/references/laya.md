# Laya policy

Read this branch whenever the selected provider is `laya`, including when init has left the global config without `providers.laya.policy`.

1. Read the global Jevvy config for the Laya endpoint and checkpoint. The defaults are `http://127.0.0.1:8000/v1/systemone` and `english`; supported checkpoint names are `english`, `multilingual`, and `typed-decisions`. Choose the target server and checkpoint before calibration; keep them stable through measurement and activation.
2. For a new or revised policy, create a separate candidate `jevvy.jsonc`, not an edit to the active global file. Set `"provider": "laya"`, preserve the intended `providers.laya` overrides, and define `providers.laya.policy` with `checkpoint` equal to the selected model and a complete, non-empty `questions` map. Use the [question format](https://github.com/PanAchy/jevvy#approval-policy) to design risk-oriented Nouls and candidate thresholds. Do not copy Jevvy's shipped Jev questions or thresholds: they auto-approved unsafe commands in an exploratory Laya run. Top-level `permissions.questions` cannot enable Laya.
3. If the server requires a Bearer key, supply `LAYA_API_KEY` to the calibration process or place `providers.laya.apiKey` in the candidate config with private file permissions. Do not expose a key in command arguments, corpora, or reports.
4. Run the shared procedure with `--config` pointing to the candidate for new or revised questions, or to the active config when only validating an unchanged policy. The result's `model` is Laya's `routing.model` and must match the selected checkpoint. `reportedModel` is the separate top-level model-family name; it does not establish checkpoint identity.
5. For a new or revised policy, wait for the shared acceptance gate and the user's approval before putting the candidate's `providers.laya.policy` in the global config. If the candidate changed the endpoint or checkpoint, update those settings together with the policy. Until then, incomplete setup leaves Jevvy unable to auto-approve; host permission prompts remain in control.
